## 用户要求与不可破坏约束

1. 回答正文保留 `[n]` 内联引用，回答结束后另有完整引用区。引用详情必须展示模型实际采用的原文段落、来源定位和适用范围；有公开 URL 时可预览并跳转，无公开 URL 时不得伪造链接。
2. 对话中展示用户可理解的 Agent 执行过程：Provider/模型显示名、公开步骤摘要、工具、状态、耗时、结果摘要和 Trace ID。联网搜索结果展示标题、来源、摘要、链接和预览。禁止向浏览器发送凭据、隐藏 Chain-of-Thought、私有 Prompt、内部安全策略、fencing token 或 Provider 原始载荷。
3. 右侧 Artifact 工作区改为类似 Word 的单页富文本编辑区：Markdown 先渲染为文档 DOM，再在成品文档上直接编辑；支持标题层级、字体大小、加粗、下划线、字体颜色、列表、链接、撤销/重做等必要能力。不得再以“上方 Markdown 源码、下方预览”的分屏作为主交互。
4. 所有导出格式都从已渲染、已编辑的文档结构生成；PDF、DOCX、图片和文本类导出不得直接输出原始 Markdown 标记。
5. 医疗问答不能因“降压、用药”等主题被机械拒绝。证据校验按 claim 局部处理：先将具体缺证据 claim 作为私有修复反馈交给同一步骤重新生成；仍不合格时只删除不合格片段，保留其余已验证内容和自然语言连贯性，不得拒绝整个回答。红旗急症短路、身份权限、真实引用和统一免责声明不因此取消。
6. 不可恢复失败必须在消息流中形成持久、可操作的自然语言消息，不能只弹短暂 toast。仅当输入本身触发不可满足的敏感/权限要求时提示“你的需求中有目前无法处理的敏感内容，请调整后再试”；网络或 Provider 故障应使用相应普通语言，不能错误归因为用户敏感输入。
7. 失败 Run 的用户输入、失败 assistant 尝试、修复反馈和工具结果不得进入后续对话的模型上下文；它们可保留为受控运行/审计事实。成功重新生成后，只允许已提交的有效 AnswerVersion 进入上下文。
8. 患者端老年模式的左上角“患者端”产品标签字号与普通模式一致，并为折叠按钮保留固定空间，避免重叠；其余患者正文与操作继续满足正文不少于 18px、控件不少于 48px。
9. 保留用户已有 dirty worktree，不覆盖或提交与本计划无关的改动。

## 视觉与交互方向

- 视觉隐喻：右栏是一张居中的“医疗文档纸张”，工作区背景与纸张形成克制层次；工具栏保持安静、紧凑、可键盘访问，不复制臃肿 Office Ribbon。
- 文档工具栏：标题/正文样式、字体大小、加粗、下划线、颜色、列表、链接、撤销和重做；每个控件有文字或 Tooltip 与可见焦点。
- 执行过程：主消息上方使用一条紧凑的运行摘要；展开后是按真实开始顺序排列的公开时间线。每一步只展示用户能理解且经过服务端 allowlist 的输入/结果摘要。
- 引用：正文角标定位 claim；文末引用卡展示采用原文；右栏或弹层提供来源预览和真实跳转。

## 完成标准

- 医疗回答正文角标、文末引用、采用原文和可访问来源形成一一对应关系。
- 运行期间可见 Provider、关键步骤、工具、耗时、结果和 Trace，且无凭据/隐藏推理/内部协议泄漏。
- 右侧可在渲染后的文档上直接富文本编辑；任何导出都不包含未渲染 Markdown 标记。
- 合法医疗问题不因主题词被拒绝；缺证据只影响对应 claim。
- 失败 turn 不污染下一轮上下文；用户始终获得稳定、自然语言、可行动的消息。
- 老年模式“患者端”不与折叠控件重叠，响应式和无障碍门禁通过。
